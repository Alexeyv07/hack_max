# KAN-7 — подключение чата

`chat_link` содержит только бизнес-flow onboarding. Хранение самих чатов и membership
остаётся в `user_chat` (KAN-5), поиск дома — в `address`.

Текущий MVP не зависит от `maxapi`: будущий UI/бот (в том числе KAN-8) должен только
вызвать handlers и отрисовать их результат.

Flow:

1. `connect_by_address(...)` принимает текстовый адрес или шестизначный индекс.
   Частные дома отклоняются; карта относится к KAN-18.
2. Если найден ровно один существующий чат, пользователь сразу добавляется в
   `users_chat`. Это mock auto-approve администратора, требуемый KAN-7.
3. Если найдено несколько чатов, handler возвращает их `chat_ids`; после выбора UI
   вызывает `connect_to_chat(...)`.
4. Если чата нет, UI спрашивает «вы администратор?», после чего вызывает
   `create_chat_link(..., is_admin=True|False)`.
   - admin: статус `pending_bot` — внешний MAX-слой позже предлагает добавить бота;
   - non-admin: `pending_admin` — токен можно передать администратору.
5. Когда внешний слой получает настоящий `chat_id`, он вызывает `bind_chat_link(...)`.
   Создаётся запись `chats`, заявка становится `ready`, автор auto-approved.
6. `connect_by_token(...)` — backend для будущей referral/deep-link. Сам формат MAX URL
   здесь намеренно не придумывается.

Статусы `ChatLinks`: `pending_bot`, `pending_admin`, `ready`, `cancelled`.
Реальное подтверждение администратора/уведомления относятся к KAN-15.
